How does a linked list actually store nodes in memory and why do we get segmentation faults when dereferencing next?

I am writing C++ code for singly linked list traversal and occasionally my pointer points to random garbage memory instead of nullptr. Can someone visualize what happens in heap memory when passing the tail node, and explain the exact sequence that causes segmentation faults?

LinkedListTraversal.cpp bug_report Segmentation Fault (SIGSEGV) 
struct Node { 
    int data; 
    Node* next; 
};

void traverse(Node* head) {
    // crash on empty list OR dereferencing final tail!
    while(head->next != NULL) { 
        head = head->next; 
    }
}

Your while loop condition while(head->next != NULL) causes two fatal issues:

  1. Null Pointer Dereference: If the list is completely empty (head == nullptr), evaluating head->next immediately faults because you dereference memory address 0x0.
  2. Tail-Stopping: The condition terminates before executing on the final node because tail->next is indeed null.

Always check the pointer itself for nullity first: while(head != nullptr). Here is the guaranteed robust pattern:

check Corrected C++ Implementation (Safe Traversal) 
void safeTraverse(Node* head) {
    // Handles empty list and processes every valid node cleanly
    while (head != nullptr) {
        std::cout << head->data << " -> ";
        head = head->next;
    }
    std::cout << "nullptr\n";
}
